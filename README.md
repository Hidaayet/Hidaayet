## `02` · How I approach problems

I am less interested in applying a model simply because it is available.

I want to understand the problem first.

```text
What is being measured?
        ↓
What does the data actually represent?
        ↓
What assumptions does the method make?
        ↓
What can the result tell us?
What can it NOT tell us?
        ↓
How can the result be evaluated?
```

From there, I try to build the complete chain:

```text
BIOMEDICAL PROBLEM
        │
        ▼
      DATA
        │
        ▼
PROCESSING / REPRESENTATION
        │
        ▼
 MODEL OR ENGINEERED SYSTEM
        │
        ▼
    EVALUATION
        │
        ▼
 INTERPRETATION
```

My repositories are therefore intended to document not only the final result, but also the **reasoning, methodology, engineering decisions, and limitations** behind it.

## `03` · Selected work

This profile contains projects across biomedical signals, medical imaging, computational biology, and biomedical AI.

Some are experiments exploring a specific method. Others are being developed into more complete engineering projects.

I am not interested in accumulating projects for the sake of having more repositories.

The goal is to progressively build the ability to take a biomedical problem from:

```text
CONCEPT → IMPLEMENTATION → EVALUATION → REPRODUCIBLE RESULT
```

and eventually toward systems and research that can be **used, challenged, improved, and built upon**.
